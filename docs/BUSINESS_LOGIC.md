# Бизнес-логика: полный перечень правил

Всё, что бот делает с нарядом **детерминированно** — без нейросети. Gemini
только распознаёт бланк и нормализует названия; каждое решение, влияющее на
деньги и на то, что уйдёт в 1С, принимается кодом из этого документа.

Порядок разделов = порядок выполнения.

| Где | Что |
|---|---|
| `src/agent_logic.py` | правила T, S, G, M, N |
| `src/validator.py` | правила V |
| `src/order_conflicts.py` | правила C |
| `src/onec_order_entry.py` | правила E |
| `data/catalog.json` | все числа и справочники |

Прогнать любой наряд через всю цепочку без Gemini и без 1С:

```bash
python tools/simulate_order.py tests/fixtures/order_base.json
python -m src.catalog_schema data/catalog.json      # проверка каталога
```

---

## 0. Источник данных: `catalog.json`

Ни одно число не зашито в код. Секции файла:

| Секция | Что задаёт | Кто читает |
|---|---|---|
| `tariffs` | `extra_point`, `transport_base`, `snos_base`, `snos_escort_base`, `snos_zhiletki` | T1, S5 |
| `digging_rules` | `kopka_person_count`, `base_price_per_person`, `towel_prices` | S2 |
| `personnel_packages` | «6200 = снос × 4» — расшифровка пакетных сумм | S3 |
| `known_unit_prices` | цена за штуку для позиций, которые пишут пачкой | G2 |
| `catalog_1c_mapping` | что и как вбивать в 1С: `name`, `price`, `search_key`, `dropdown_index`, `aliases` | M1–M6 |
| `services_list` | официальные названия услуг | N1–N4 |

> `snos_base` / `snos_escort_base` / `snos_zhiletki` сейчас **не читаются
> напрямую** — они работают через `personnel_packages` (правило S3) и через
> подбор по цене (M4). Если понадобится правило, зависящее от ставки как
> таковой, брать её надо из `tariffs`, а не из константы в коде.

## 1. Подготовка (T)

**T1. Цена за единицу.** Для каждой позиции всех трёх категорий:
`unit_price_for_1c = price // max(1, quantity)`. В бланке `Сума` — это итог
по строке, а в 1С вбивается цена за штуку.
*Деление целочисленное: 1001 / 2 → 500.*

---

## 2. Услуги (S)

Выполняются построчно, в этом порядке. Первое сработавшее правило
завершает обработку строки.

**S1. Удаление дублей из 1С.** Если название (в нижнем регистре, с
схлопнутыми пробелами) совпало с позицией, уже найденной в открытом наряде
1С, строка выбрасывается с предупреждением. Защита от двойного ввода.

**S2. Отделение рушника от закопки.** Если в названии есть `закопув` **и**
`price >= kopka_person_count × base_price_per_person + min(towel_prices)`
— строка делится: закопка по базовому тарифу остаётся в услугах, разница
уходит в товары отдельной позицией «Рушник для опускання».
*При текущем каталоге порог = 7700 + 1400 = 9100. Ровно 7700 не делится —
это закопка без рушника (проверено на VIP-наряде).*

**S3. Расшифровка пакета персонала.** Если сумма строки точно совпала с
ключом `personnel_packages` — количество и цена за человека берутся из
пакета, название заменяется на пакетное.
*6200 → снос × 4 по 1550. Срабатывает, только если количество в бланке
отличается от пакетного; если бланк уже расписан правильно — не трогает.*

**S4. Подсчёт персонала.** Строки со словами `снос` / `персонал` / `ескорт`
прибавляют своё количество к счётчику людей; `церемоніймейстер` прибавляет 1.
Счётчик нужен для S5.

**S5. Доп. точки маршрута.** Если оператор указал N > 0 дополнительных
адресов:
* услуги: `+1` строка, количество = `персонал × N`, цена = `extra_point` за
  единицу;
* транспорт: `+1` строка, количество = `машины × N`, цена = `transport_base`.

**S6. Перенос в товары.** Строки со словами `рушник` / `хусточки` / `свічки`
/ `набір` / `комплект`, попавшие в услуги, переносятся в товары — там
работает маппинг по каталогу товаров.

---

## 3. Товары (G)

**G1. Категория по ключевому слову.** Название сопоставляется с
`CATEGORY_KEYWORDS`, **первое совпадение выигрывает — порядок важен**:

| Категория | Ключевые слова |
|---|---|
| `coffins` | труна, гроб |
| `wreaths` | вінок, венок |
| `baskets` | корзина |
| `plaques` | табличка |
| `crosses` | хрест, крест |
| `towels` | рушник, отче, полотенце |

> `plaques` стоит **выше** `crosses` намеренно: в бланке есть строка
> «Табличка на хрест» — в ней оба слова, и это табличка. При обратном
> порядке строка уходила в кресты, где табличек нет, и не сопоставлялась
> никогда.

**G2. Починка количества по known_unit_prices.** Для позиций вне категорий:
если название содержит известное имя, `quantity == 1`, и итог делится
нацело на цену за штуку — количество восстанавливается.
*«Хусточки 800» → 20 шт по 40.* Читается только **первая** цена из списка:
`"Хусточки": [40, 45]` — 45 не используется.

## 4. Сопоставление с 1С (M)

Самая ответственная часть: результат уходит в чужую программу, где **отмены
нет**. Порядок проверок — от самого надёжного признака к самому слабому.

| # | Правило | Признак | Результат |
|---|---|---|---|
| **M1** | Точное имя | название == имени в каталоге | ✅ сопоставлено |
| **M2** | Имя без пунктуации | «снос ескорт» == «снос-ескорт» | ✅ сопоставлено |
| **M3** | `aliases` | название в списке синонимов позиции | ✅ сопоставлено |
| **M4** | Частичное имя | название — подстрока имени каталога, **в пределах своей цены** | ✅ сопоставлено |
| **M5** | Единственная цена | ровно одна позиция с такой ценой и название похоже | ✅ сопоставлено |
| **M6** | Несколько позиций по цене | выбирается по схожести названия (порог 0.45) | ⚠️ помечается «сверь» |

**Отказы — тоже правила.** Отказ означает ручной ввод, и это штатный исход:

* **M-R1. Цена не совпала.** Частичное совпадение имени при другой цене
  отклоняется. *«Рушник на хрест 380» похож и на 250, и на 350 — ни один не
  380; это другой вариант товара, а не скидка.* Точное совпадение имени
  (M1) от этого правила освобождено — там оператор просто изменил цену.
* **M-R2. Только цена, без сходства имён.** Совпадение цены при непохожих
  названиях (схожесть < 0.35) отклоняется. *«Насипний пагорб» за 1200 грн
  совпадает по цене с «Перевезення покійного» — это совпадение, а не смысл.*
  Если связка верная — закрепить через `aliases` (M3).
* **M-R3. Позиция без цены.** Строки «б/ч» (`price = 0`) не сопоставляются
  частично: «Труна» — подстрока сотни наименований гробов, выбор был бы
  случайным. Точное имя и `aliases` работают.
* **M-R4. Пустой `search_key`.** Позиция каталога без ключа поиска не
  используется — вбивать в 1С нечего.

### Как добавить связку, которую строками не вывести

```json
{
  "name": "снос (Галстук)", "price": 1550,
  "search_key": "снос", "dropdown_index": 9,
  "aliases": ["Послуги персоналу для поховання", "Послуги персоналу"]
}
```

Один alias можно повесить на несколько вариантов — нужный выберет цена.
После правки: `/reload_catalog` в боте (перезапуск не нужен).

## 5. Нормализация названий услуг (N)

Приведение к `services_list`, по порядку:

**N1.** Точное совпадение без учёта регистра.
**N2.** Совпадение без пунктуации («снос ескорт» → «снос-ескорт»).
**N3. Сокращение.** Если название — часть официального, берётся **самое
короткое** подходящее: «Закопування» → «Закопування/опускання труни».
**N4. Составная ячейка.** Если наоборот, официальные названия входят в
название строки, берётся **самое длинное**: «Насипний пагорб/Встанов.
хреста» → «Насипний пагорб».
> Направления разные намеренно. При едином правиле «самое короткое» ячейка
> схлопывалась в «Хрест» — товар, а не услуга, — и дальше по цене 1200
> уезжала в «Перевезення покійного».

**N5. Нечёткий поиск.** Порог схожести **0.8**, и только если второй
кандидат отстаёт минимум на 0.05. Иначе название остаётся как в бланке.
> Прежний порог 0.6 переименовывал «Автотранспорт для поховання» в
> «Автотранспорт під вінки» (0.72 на общем префиксе). Опечатки распознавания
> набирают куда больше: «Ктафалк» → «Катафалк» это 0.93.

**Ограничение:** составная ячейка (N4) сохраняет **одну** услугу из
нескольких. «Насипний пагорб/Встанов. хреста» за 1200 → одна строка
«Насипний пагорб». Вторая услуга теряется. Разделение требует знания, как
делить сумму, — этого в бланке нет.

## 6. Валидация (V)

**V1.** Схема Pydantic: отрицательная цена или количество — позиция
выбрасывается, наряд сохраняется.
**V2.** Календарные галлюцинации распознавания чинятся в датах смерти и
похорон.
**V3.** Пустая дата смерти → сегодняшняя.
**V4.** `calculated_total` пересчитывается по строкам — это итог, которому
доверяет сводка.

## 7. Сводка и конфликты (C)

**C1. Расхождение сумм.** Если сумма с бланка отличается от расчётной
больше чем на **1 %** — конфликт.
**C2. Нет даты рождения.** Дата `01.01.1920` — маркер «не распознано».
**C3. Строки без соответствия в 1С.** Всё, что не прошло M1–M6.
**C4. Строки «сверь».** Сопоставленные по M6.
**C5. Блокировка автоввода.** `can_auto_enter = False`, если есть хоть одна
строка из C3. Расхождение сумм и отсутствие даты рождения показываются, но
ввод не блокируют.

---

## 8. Ввод в 1С (E)

**E1. Вкладки:** услуги → `tab_uslugi`, товары → `tab_sklad`, транспорт →
`tab_prochie`.
**E2.** Позиция без `1c_search_key` **не вводится** — исключение вместо
слепого нажатия.
**E3.** Ввод: `search_key` → `↓ × dropdown_index` → Enter → Tab →
количество → Enter.
**E4. Защита RDP.** В боевом режиме ввод запрещён, пока RDP не в состоянии
`connected`.
**E5. Dry-run** (по умолчанию) — только лог, ни одного нажатия.
**E6.** Первая ошибка останавливает наряд целиком.

## 9. Проверка каталога (K)

`python -m src.catalog_schema` и `/catalog_check` в боте. Ошибки ломают
секцию, предупреждения — повод посмотреть глазами.

| Код | Что значит |
|---|---|
| `STRUCTURE` / `SECTION_DROPPED` | секция не проходит схему и отброшена |
| `DUPLICATE_PRICE` | две позиции одной категории с одной ценой → подбор по цене неоднозначен |
| `DROPDOWN_COLLISION` | `search_key` + `dropdown_index` указывают на разные позиции → верна максимум одна |
| `BLANK_SEARCH_KEY` | позицию нельзя ввести автоматически |
| `UNKNOWN_CATEGORY` | категория не разбирается кодом (см. G1) |
| `PACKAGE_MATH` / `PACKAGE_TARIFF` | пакет персонала не бьётся с тарифами |
| `TOWEL_UNMAPPED` | цена рушника из `digging_rules` не встречается в каталоге |
| `KNOWN_PRICE_UNMAPPED` | позиция чинится по количеству, но в 1С уйдёт вручную |

## 10. Куда добавлять новые условия

| Что нужно | Куда |
|---|---|
| Новый тариф / ставка | `catalog.json` → `tariffs`; читать через `TARIFFS.get(...)` |
| Новый пакет персонала | `catalog.json` → `personnel_packages` (правило S3 подхватит) |
| Новая цена за штуку | `catalog.json` → `known_unit_prices` |
| Связка «бланк ↔ 1С» | `aliases` у позиции каталога (M3) |
| Новая категория товаров | `CATEGORY_KEYWORDS` в `agent_logic.py` + секция в `catalog_1c_mapping` + в `KNOWN_MAPPING_CATEGORIES` |
| Новое правило по услуге | ветка в цикле `for s in services` (`apply_business_rules_in_python`) |
| Новый вид конфликта | поле в `OrderSummary` + вывод в `summary_formatting.py` |
| Новая проверка каталога | функция в `catalog_schema.py` + код в таблице раздела 9 |

Любое изменение прогонять на трёх реальных нарядах:

```bash
pytest tests/test_base_order_e2e.py tests/test_real_orders.py -q
python tools/simulate_order.py tests/fixtures/order_vip.json
```

## 11. Известные пробелы

Найдены на реальных нарядах, **сейчас не закрыты** — фиксирую, чтобы решать
осознанно:

1. **Задаток и остаток не моделируются.** В бланке есть «Завдаток 21000 /
   Залишок 820»; в заказе — только итог. Ни в сводке, ни в 1С не попадают.
2. **Составная ячейка теряет вторую услугу** (см. N5).
3. **`known_unit_prices` использует только первую цену** из списка, хотя
   схема — список. Наряд с «Свічки 10 × 35» при заявленных 30 не чинится:
   35 не делится на 30, количество остаётся как распознано.
4. **Цены, которых нет в каталоге, не подсказываются.** «Труна 3800» при
   наличии 3650 и 3900 просто уходит в ручной ввод — без подсказки
   ближайших вариантов.
5. **Ставка персонала вне тарифов не распознаётся.** 4 × 2050 = 8200 из
   второго наряда не сопоставляется: ни 2050 в `tariffs`, ни 8200 в
   `personnel_packages`. Лечится добавлением в каталог.
6. **`catalog_1c_mapping.services` покрывает 7 позиций** при 102 услугах в
   `services_list` — поэтому большинство услуг уходит в ручной ввод. Это
   не дефект кода: соответствий в каталоге пока нет.
7. **Коллизия `Рушник н` #1** в боевом каталоге: один и тот же слот
   выпадающего списка 1С занят и «Рушник на хрест 250» (towels), и «Рушник
   на хрест 350» (crosses). Верна максимум одна — нужно свериться с 1С.
